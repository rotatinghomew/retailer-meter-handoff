# 售电交接数据约定
计量点按 meter_id 唯一标识，读数是累计整数 kWh，边界时刻带时区。按相邻断点的差值计量，边界前区间归旧合同、边界开始归新合同；`tariffs` 的单价是示例账期固定的分/kWh，两边使用同一认可读数分割总量。用量依据 `reads` 中相邻 time 及其累计读数计算。估抄不能结清，confirmed 可以成为正式断点，修订号和 revises 识别计量方的正式更正。
`requests` 由企业发起，group 为 both 时表示相关计量点须同批改变商业责任，否则是 separate。both 回执部分成功时，客户在 `bridge_terms` 冻结临时商业责任人和过渡价。物理未切换的点仍由原合同正常承担，已切换的点从各自物理断点进入临时商业责任。最后一点成功时，该批按最后成功点确立正式商业切换日，早切点到该时刻采用临时条款，若剩余点不再办理，则临时条款持续到客户另签接收约定。期间的独立账按实做，不提前让未生效的合约承担。
计量接口每个请求返回 events，单点的 applied 表示物理交界成立，declined 表示明确失败，accepted 仅代表受理。带 `change_id` 和 `meter_id` 的事序以计量方时间和 revision 判定，接受后的旧 accepted 回执不能撤销已完成事实。若撤回和生效交叉，计量方先记录的有效事件决定是否已切；撤回得到明确接受前，不能证明上一笔没有生效。事件仅用于本请求的计量点。
## 资料发布
报文样例位于 `data/`，每个集合是一个 UTF-8 JSON 数组，id 是集合内的来源标识。跨集合引用使用原标识。没有值的可选项可以不提供，JSON null 表示已报告但暂未确认的值。

## 外方接口联调
`data/peer.json` 每一项给出相对 HTTP 路径、提交体和外方回执。用 POST 提交应用 JSON，GET 经同一地址查询。查询会推进这段联调记录，最后一个回执可以重复查。`drop_first_reply` 使外方在第一次匹配的 POST 后关闭连接，已收到的请求可再查询。重送相同请求可读当前回执，换内容仍占用旧请求号时返回 409。联调方重启后重新开始一轮。
